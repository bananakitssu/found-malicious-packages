## Summary

Potential Unauthorized Server Control if DAT Credential Is Compromised

## Details

The package includes administrative API endpoints that can restart or shut down the server. These endpoints are protected by a DAT credential configured by the developer and sent as a cookie. The security of these administrative operations therefore depends on the confidentiality and proper configuration of the DAT. If the DAT is leaked, exposed, or otherwise compromised, an attacker who can reach the administrative endpoints may be able to perform privileged server actions.

Observed behaviors:
- Runtime process control (restart/shutdown) via HTTP endpoints
- Administrative access protected by a developer-configured DAT credential
- Browser network traffic interception and monitoring for development tooling

Evidence:
- `dist/cli.js` — The class App exposes POST endpoints such as /__authtics_host_apis__/restart and /__authtics_host_apis__/shutdown which use child_process.spawn and process.kill to manipulate the server lifecycle.
- `dist/devPanel.js` — The function installNetworkInterceptor monkey-patches global fetch, WebSocket, and EventSource to monitor and log network activity, which is consistent with development tooling.
